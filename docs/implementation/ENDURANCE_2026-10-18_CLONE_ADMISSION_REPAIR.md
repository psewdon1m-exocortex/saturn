# Индекс допуска clone-content, 18 октября 2026

Миграция `0069_clone_admission_index` добавляет частичный индекс журнала по
`sync_root_id` для незавершённых `clone-content`. Условия допуска, лимиты,
подписи функций, оригиналы операций и протокол не меняются. Без индекса ветка
`sync_policy_admission` просматривает всю историю журнала при каждой новой
загрузке, даже если ожидающих клонирований нет.

На тестовом стенде до исправления запрос просмотрел 34 946 строк Windows-корня.
После миграции используется индекс. Измерения этой ветки SQL: Windows
18.192 → 0.053 мс; Pluto 13.412 → 0.042 мс. Эти значения не означают такого же
ускорения всей синхронизации.

Адресная проверка `apps/api/src/sync-clone-admission-index.integration.test.ts`:
30 000 исторических записей, индексный план, настоящее клонирование и чтение
байтов, повтор с тем же ключом, down/up с сохранением оригинальных receipts и
исходников всех функций. До правки проверка плана упала, после прошла.

Для обновления используется обычная пара up/down мигратора. Down удаляет только
индекс. Старые серверные процессы продолжили работать после добавления индекса
на двух тестовых БД без смены bindings/epoch. Не требуется миграция клиентского
состояния. Обычный CREATE INDEX может кратковременно задержать записи; на
нагруженном развёртывании следует учитывать размер журнала и окно миграции.
В текущем тестовом применении ожидание блокировки ограничивалось 2 секундами,
выполнение — 30 секундами, DDL и запись истории выполнялись в одной транзакции.
