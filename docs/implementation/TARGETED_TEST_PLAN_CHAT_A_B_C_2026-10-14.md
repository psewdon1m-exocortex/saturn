После последней правки один итоговый запуск затронутого набора на итоговых исходниках. Не повторять весь pipeline после каждой правки.
5. Не запускать `pnpm test`, `pnpm -r ...`, `verify:*`, solution-wide `dotnet test`, `go test ./...`, общие нагрузочные/6h сценарии. Допустимы точечная компиляция изменённого компонента и перечисленные tests. Старый широкий harness использовать как библиотеку fixture, а не запускать целиком ради одного assertion.
6. Никаких тестов на рабочих vault/profile/БД/remote root. PostgreSQL, SFTP, HTTP, filesystem, registry и installer — disposable fixture. Для каждого lane отдельные БД/роли/roots/порты/профили. Убийство процесса — только по сохранённому PID и проверенному пути своего helper; сетевой fault — только на соединении своей fixture. Соблюдать реальные OS/FS свойства; mock не заменяет native gate.
7. Состояние времени retry/debounce проверять через управляемые часы/barriers; не ждать реальные минуты backoff. Числа 750 ms/5 s/лимиты ниже — контракт системы, не ограничение времени работы чата. Для native проверок нужны реальные события и измерения; watchdog прекращает зависший тест с FAIL и dump, а не превращает его в PASS.
8. Параллелить только lanes с разными ресурсами. Сборки одного проекта, миграции одной БД, изменение общих env vars, native updater/registry/installer, perf comparisons и fault injection на одном backend выполняются последовательно. Не включать `t.Parallel()` для process-global scheduler/proxy/clock fixtures. Не модифицировать файл, пока его используют запущенные тесты; дождаться своего lane и пересобрать.
9. SKIP, нулевое число выбранных тестов, отсутствующий native стенд, compile overlay, `NoWarn` для обхода новой ошибки, timeout и инфраструктурный отказ **не равны PASS**. Для незапущенного обязательного gate статус BLOCKED/NOT RUN с конкретной причиной. Не выдавать все требования за закрытые.
10. Из production diagnostics исключать credentials/содержимое. В test evidence сохранять fixture operation IDs, hashes, counts, receipts, SQL state, trace последовательности; секреты и полный environment dump не сохранять.

Если CHAT-B и network чат тестируют один Neptune checkout, общий `bin/obj` защищать **удерживаемым OS file lock**, а не наличием marker-файла: `.audit/2026-10-14/targeted-tests/locks/neptune-build-run.lock`, `FileShare.None`. Захват до build, освобождение после завершения всех своих `--no-build` процессов; внутри владельца lock независимые фильтры могут работать параллельно. Ожидающий чат продолжает Go/ingress/документацию. Для полной параллельности допустима собственная source copy со всеми актуальными uncommitted файлами, isolated build outputs и recorded hashes; простого checkout HEAD недостаточно. Аналогично исключить одновременный `--clean` package build и тестирование его dist. Source hash, изменившийся во время запуска, требует повторить только affected tests на финальном состоянии.

Формат журнального события:

```text
## <реальные YYYY-MM-DDTHH:mm:ss+03:00> — <ID теста / действие>
- Причина:
- До / входной гейт: source SHA, fixture, ожидаемое поведение, предыдущий FAIL.
- Что и как сделано: точная команда/filter, fault point либо изменение файлов.
- Выходной гейт: PASS / FAIL / BLOCKED / NOT RUN; selected/passed/failed/skipped,
  наблюдаемый результат, assertions, путь к raw log/TRX/JSON/trace.
```

Каждый итоговый отчёт содержит таблицу всех ID своей группы и подвариантов, исправленные defects, исходники после исправления, оставшиеся gates и ссылки на журнал. В журнале фиксировать начало длительного сценария и его завершение; не восстанавливать хронологию задним числом по памяти.

## 2. Общие fixtures и команды

### Данные и fault points

- Каждый тест получает собственные root/device/backend UUID и отдельные версии/operations. UUID фиксировать в fixture manifest, повтор crash/restart использует **те же** IDs.
- Набор F: пустой файл; 1 KiB и 64 KiB файлы; 8 MiB + 1 byte для early-streaming; 12 MiB + 17 bytes для нескольких chunks; один файл 256 MiB и один 256 MiB + 1 byte для Pluto cap. Байты детерминированы seed=314159, SHA вычисляется независимым reader. Native имена: `Агентность, локус контроля, инициативность.md`, `COMLPT1.md`, вложенная пустая директория.
- Операция на fixture проходит controllable points: до durable prepare; после prepare commit до ответа; после приёма chunk до ACK; после publication commit до ответа; после local receipt до dirty ACK. В этих точках оборвать только fixture request/process, открыть новый client/store и проверить сохранённые originals. Это проверка идемпотентности изменённого engine, не повтор полного сетевого набора.
- До/после сравнивать original canonical JSON/hash, operation/upload/batch IDs, expected versions, chunk ACK map, generation, current version, исторические receipts и реальный SHA файла. Для g+1 создать изменение после claim g, до его ACK.
- Shared codec fixture: `saturn/packages/contracts/fixtures/name-codec-v1.json`. Каждый язык исполняет **все** vectors этого небольшого изменённого контракта; добавляет NFC/decomposed, ASCII case collision, reserved name, trailing dot/space, slash/backslash, traversal и invalid UTF-8/Unicode на доступной границе parser.

**Повтор после исправлений C:** codec→C05+A01/B15 vectors; observer/state→C02/C03+late ACK variant; engine→соответствующий C07/C08/C09 и original restart; verifier→соответствующий C14–C16 плюс A12 contract example. Сетевые Go tests не запускать одновременно с process-global environment changes.
