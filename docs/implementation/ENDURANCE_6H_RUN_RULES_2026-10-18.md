## Время и управление

- Подготовка корпуса/сборок до T0. При старте T0 записывается один раз; deadline=T0+21600 секунд. Простои/исправления входят в окно. Resume не меняет T0.
- Каждые 30 минут агент проверяет результаты, реальные PID/creation time, freshness полезного прогресса, очереди и ресурсы. Контроллер пишет метрики и журнал чаще. После окончания автоматизация отключается.
- После deadline запрещены новые циклы/ступени/сценарии. Последний реально начатый цикл, включая уже работающие параллельные направления, завершается с readback и необходимыми адресными исправлениями/повторами.

- 500000 реальных файлов в одном источнике Neptune; каталоги считаются отдельно. Не менее 20 GiB фактических исходных данных. Подтверждённая публикация и независимое полное readback обязательны. Созданный корпус без сходимости — не PASS.
- Не менее 20 одновременно выполняющихся независимых backup-задач Pluto/Saturn с разными источниками/state. Измеряется фактическое пересечение времени работы, файлы/байты каждой задачи. HTTP concurrency не подменяет количество backup-задач.
- Все реализованные пользовательские цепочки четырёх проектов инвентаризируются. Матрица базируется на 40 группах правил 15 октября, дополняется текущими функциями. Частичная проверка группы не делает всю группу PASS.
